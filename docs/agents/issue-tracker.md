# Issue tracker

**Project:** [capyBearista/decisionbench](https://github.com/capyBearista/decisionbench)  
**Tracker:** GitHub Issues; PRs are reviewed through GitHub.

Use GitHub Issues for accepted specifications and implementation work. An implementation issue should describe one independently demonstrable vertical slice, explicit acceptance criteria and genuine blockers. Prefer native GitHub blocking/sub-issue relationships where available, otherwise include a concise **Blocked by** section.

The canonical specification is the versioned repository file [docs/SPEC.md](../SPEC.md). A specification issue can index it for planning and link its review PR; do not maintain two divergent copies of implementation decisions. Changes that alter agreed product behavior should update the spec (and any relevant ADR) before implementation tickets are issued or revised.

Issues generated from a reviewed specification are already implementation-ready; incoming reports can be triaged separately if needed. Do not assume any specific triage labels exist until they have been verified/configured.
